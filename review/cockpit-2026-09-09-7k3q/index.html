제안

Mother·Opus·Praxis·Astra를 한 화면에서 만나고, 지시가 어디까지 갔는지와 결과를 확인하는 코크핏을 유지한다. 연결은 지원되는 공식 인터페이스부터 단계적으로 바꾼다. 사용자는 엔티티를 고르며, 엔티티와 실행 세션을 연결하는 일은 시스템이 맡는다.

첫 구현은 새 화면 전체가 아니라 한 문장을 정확한 상대에게 보내고, 다른 탭·PC·폰으로 이동해도 그 결과를 찾는 흐름이다. 공동 회의와 결과물 보기의 화면 시안은 같이 검토하되, 실시간 다자 실행은 기본 송수신 검증 뒤로 둔다.

이 문서는 제안이다. 코크핏 종료, 새 런타임 도입, 계정·비용 변경은 시행하지 않았다.

2. 현 상태: 이미 있는 것과 아직 부족한 것

사용량 두 줄, 실제 응답 모델 배지, 대화/터미널 전환, 엔티티별 초안 저장, 한글 조합 보호, 출력 팬아웃은 이미 있다. 이를 새 성과로 다시 세지 않는다. 이번에 현재 코드에서 확인한 장애 경로는 다음과 같다.

  1. 교차 탭 영수증 문제를 발견했고 부분 수정됐다. 마더에 전송한 뒤 오퍼스 탭으로 옮기면 늦게 돌아온 마더 영수증이 오퍼스 화면에 표시되는 경로를 격리 시험에서 재현했다. Mother가 응답 후 탭 가드를 추가했고 Astra가 같은 탐침으로 수정 효과를 확인했다. 기존에 그려진 영수증이 탭 전환 뒤 남는 문제와 메시지별 보관은 별개로 남아 있다. 재현·수정 확인 코드.
  2. 시간 초과의 표시가 지나치게 확정적이다. 8초/부팅 45초 안에 수신 증거를 못 찾으면 「도착 못 함」과 수동 재전송 버튼을 제공한다. 현재 자동 재전송은 없다. 표시를 「수신 확인 지연」으로 바꾸고, 재전송 전 기존 요청 상태를 확인하도록 제안한다. 재전송 버튼 자체를 없애자는 안은 아니다. 실제 처리됐으나 영수증이 늦은 경우와 구별해야 한다. 중복 실행 자체는 이번에 재현하지 않았다.
  3. 상태가 메시지별이 아니다. 영수증 타이머 하나와 일부 hook 시각 비교로 추적한다. 여러 탭의 진행·동일 문장 재전송·주인 세션 교체를 정확히 연결하기 어렵다.
  4. 편지 감지와 읽음은 다르다. native-bell의 seen은 파일 발견 기록이다. 이번 r5 세 통은 상대 실제 읽기·보관 기록까지 확인했지만 자동으로 같은 보장을 제공하지 않는다.

별도 감사의 발신 파일 동시 쓰기 문제는 Mother가 배타적 생성으로 수정한 현재 코드를 확인했다. 미수정 결함 목록에서 제외한다.

3. 세 대안

안장점남는 문제판단
현재 코크핏 보수기존 세션·사용 습관 유지, 작은 수정 가능터미널 입력 타이밍과 기록 형식에 의존이행 기간에 필요
통합 화면 + 엔티티별 공식 연결한 화면과 혼합 모델을 유지하며 제어·관측 정확성을 높일 수 있음Claude와 Codex의 지원 범위가 다름. 인증·세션 인수 시험 필요조건부 권고
Claude 화면과 Codex 화면으로 분산자체 화면 유지비 감소 가능사용자가 회의·상태·결과를 다시 모아야 함비교 대안, 기본안 아님

Mother 1차 회의는 혼합안을 지지했다. Astra의 「Astra 폰 발화 0은 수요 부재 증거가 아니다」와 「줄 수 절감만으로 UX 개선을 입증할 수 없다」는 이견을 수용했다. Mother의 반론도 채택한다: 유지보수 실패로 생기는 깨짐과 복구 대기는 사용자 비용이다. 따라서 코드 줄 수보다 잘못된 전달·복구 시간·수동 중계 횟수를 본다.

4. 화면과 일의 흐름

공통 화면

  • 상단 두 줄: Claude 계정별 사용량 / Astra 사용량. 측정 시각·갱신 실패를 함께 표시한다. 모르는 값을 0으로 그리지 않는다.
  • 엔티티 목록: 이름, 실제 모델, 현재 하는 일 또는 필요한 응답. 세션 주소·내부 로그는 상세에서만 본다.
  • 본문: 개별 대화 / 회의 / 결과물. 기본 진입은 마지막 대화. 회의가 제품의 상시 기본 홈이어야 하는지는 미확정이다.
  • 하단: 받는 사람이 보이는 입력창 하나. 상대·회의별 초안 보존. 전송은 해당 메시지에 상태를 붙인다.
  • 승인 요청이 있으면 본문 가까이에 구체 요청·대상·선택지를 표시한다. 요청이 없는 상태에 가짜 승인 버튼을 띄우지 않는다. 재연결·중단·재시작은 대상 엔티티의 작업 메뉴에서 접근한다.
  • PC에서는 근거·결과를 옆에, 폰에서는 접어 읽는다. 터미널은 상세 보기로 유지하며, 동등한 제어가 검증되기 전 제거하지 않는다.

대표 장면 A: 지시하고 다른 일을 본다

  1. Astra에 긴 한국어 지시를 쓰고 보낸다.
  2. 해당 말풍선에 「접수됨」 또는 「수신 확인 중」이 표시된다. Mother 탭으로 옮겨도 Astra의 기록이 살아 있다.
  3. 브라우저 연결이 끊기면 「연결 끊김 · 처리 여부 확인 중」으로 표시한다. 자동으로 같은 지시를 새 실행으로 보내지 않는다.
  4. 재연결 후 같은 메시지의 실제 진행과 결과를 이어 보여준다. 완료는 결과물·검증 기록과 연결한다.

대표 장면 B: 둘과 회의한다

대표님이 주제와 참여자를 정한다. 첫 의견은 참여자별로 구분해 보관하고, 반론·수정·합의가 어떤 원문에서 왔는지 연결한다. 「두 명이 답함」은 「합의함」이 아니다. 응답 없는 사람은 미응답, 받아들이지 않은 내용은 이견으로 남는다. 합의 초안을 대표님 확정으로 바꾸지 않는다.

첫 회의 화면은 기존 편지 왕복을 읽어서 보여준다. 이미 작동하는 대화를 주제·참여자·이견/합의·원문 링크로 모으며 새 발송 체계를 동시에 만들지 않는다. 회의 쓰기·자동 진행은 후속 범위다. 쓰기를 도입하면 진행자가 필요한 발언만 지정 상대에게 전달한다. 기본 진행 제안은 독립 의견 → 쟁점별 반론 → 결론 초안이며, 더 돌릴지는 진전과 사용자 지시로 판단한다. 자동 무한 대화는 피한다. 회의 주제·참여자·결과물·근거만 보존하고 내부 추론을 표시 대상으로 삼지 않는다.

대표 장면 C: 승인하고 이어간다

폰에서도 어느 엔티티의 어떤 작업인지 확인하고 그 요청에 응답한다. 세션이 바뀌어 만료된 요청은 실행되지 않는다. 공식 경로로 처리할 수 없는 요청은 지원되는 원래 화면으로 안내한다. 번호 키를 맥락 없이 눌러 성공한 것으로 간주하지 않는다.

엔티티 ID는 지속되고 세션 ID는 재시작마다 바뀔 수 있다. 같은 집에 창이 여러 개 있으면 현재 작업 주인을 명시적으로 선택해 기록한다. 파일 수정시각만으로 주인을 바꾸지 않는다. 입력 담당을 하나로 정하고, 다른 화면은 같은 사건을 구독한다.

메시지에는 고유 ID·대상 엔티티·세션·응답 실행 ID를 연결한다. 재연결 요청은 같은 메시지 ID를 재사용한다. 아래 런타임이 중복 제거를 제공하지 않는 경우 정확히 한 번 실행을 약속하지 않는다. 전송 결과가 애매하면 조회·대조 후 사용자가 다시 보낼 수 있게 한다. 공통 상태는 접수/진행/사용자 응답 필요/완료/오류·확인 불가 정도로 두고, 파일 감지·전송·수신·처리의 세부 증거는 상세에 남긴다.

Codex: 공식 App Server 문서와 설치 0.153.4 스키마에서 대화 읽기·재개, 턴 시작·추가 지시·중단, 이벤트, 사용량 경로를 확인했다. 현재 TUI 세션을 그대로 인수할 수 있는지, 지시 파일·권한·도구 구성이 동일한지는 미검증이다. 어댑터 200줄로 충분하다고 확정하지 않는다. 공식 문서

Claude: SendMessage는 세션 사이의 메시지 전달이다. 웹 앱에서 직접 호출하는 범용 승인·중단 API로 확인된 것이 아니다. Remote Control은 로컬 세션의 폰·브라우저 조종 경로다. Agent SDK는 프로그램 통합 후보이나 현재 개인 구독·인증·비용이 그대로 이어진다고 가정하지 않는다. 첫 단계에서 가능한 연결과 미지원 조작을 표로 확인한다. 메시징, Remote Control, Agent SDK

외부 폰 접속은 현재 인증된 연결 또는 지원되는 원격 경로를 이용한다. localhost 개발 화면을 그대로 공개하는 방식은 제안하지 않는다. 어떤 화면에서 보내든 동일 작업의 승인·상태가 중복되거나 엇갈리지 않아야 한다.

"""Inspect the offline proposal UI in an isolated headless browser. No agent requests."""
import asyncio
import base64
import json
import subprocess
import tempfile
import time
from pathlib import Path
from urllib.request import urlopen

import websockets

HERE = Path(__file__).resolve().parent

async def inspect(port):
    pages = json.load(urlopen(f'http://127.0.0.1:{port}/json', timeout=5))
    page = next(p for p in pages if p['type'] == 'page')
    async with websockets.connect(page['webSocketDebuggerUrl'], max_size=10_000_000) as ws:
        seq = 0
        async def call(method, params=None):
            nonlocal seq
            seq += 1
            ident = seq
            await ws.send(json.dumps({'id':ident,'method':method,'params':params or {}}))
            while True:
                msg = json.loads(await ws.recv())
                if msg.get('id') == ident:
                    if 'error' in msg:
                        raise RuntimeError(msg['error'])
                    return msg.get('result', {})

        async def evaluate(expr):
            result = await call('Runtime.evaluate', {'expression':expr,'returnByValue':True,'awaitPromise':True})
            if 'exceptionDetails' in result:
                raise RuntimeError(result['exceptionDetails'])
            return result.get('result',{}).get('value')

        async def screenshot(name):
            await evaluate('document.fonts.ready.then(()=>new Promise(r=>requestAnimationFrame(()=>requestAnimationFrame(r))))')
